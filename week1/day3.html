Day 3 · 集团科目表与主数据

FS Item与Group CoA映射、Subitem/Transaction Type、CRUD API（2402）、时间相关层级
⏱ 约45分钟📖 主数据设计

3.1 Financial Statement Item（FS Item）

FS Item 是 Group Reporting 的核心主数据，相当于集团层面的"会计科目"。每个本地公司的 GL Account 需要映射到统一的 FS Item，才能在集团报表中汇总。

概念说明华照示例
FS Item集团财务报表项目（集团科目）110001（应收账款集团科目）
Local GL Account各法人本地科目表科目佛山总部：113100；高明：1131（不同编码规则）
FS Item HierarchyFS Item 层级结构，用于报表行项目资产负债表 > 流动资产 > 应收账款
Subitem（Transaction Type）B/S 科目的细分（资产负债表变动类型）期初余额/本期增加/本期减少
Functional AreaP&L 科目的功能区域细分（按成本法）销售费用/管理费用/财务费用

3.2 集团科目表 vs 本地科目表

华照挑战：19家法人使用 5 套不同的本地科目表，需要统一映射到集团科目表（Group Chart of Accounts）。MDG-F 模块（主数据治理）负责维护集团科目表，确保唯一写入点（IS-01原则）。

3.3 2402 新功能：时间相关 FS Item 层级

自 S/4HANA 2402 起，FS Item 层级支持时间相关版本（Time-Dependent Hierarchies）。同一层级可在不同日期有不同结构，通过 Valid From / Valid To 日期控制。

使用场景：如果华照集团在 2027年 调整组织架构（如新成立一个事业部），可以创建新的层级时间片，而不影响历史合并数据。
注意：不同时间片的 Valid To 不能重叠；消费层级时必须指定 Key Date。

3.4 CRUD API（2402）

API 名称功能支持操作
API_CONSOLIDATIONUNIT合并单元主数据Create / Read / Update / Delete
API_CNSLDTNFSITEMFS Item 主数据Create / Read / Update（不支持Delete）
为什么 FS Item 不支持删除？因为 FS Item 一旦被历史合并数据引用，删除会破坏数据完整性。如需"删除"，应使用 Block 标志禁用，保留历史记录。

📝 知识测验 — Day 3

Q1. 华照佛山总部的本地科目 113100 对应集团合并科目 110001，这个映射关系叫什么？
✅ FS Item Mapping 定义了本地 GL Account 与集团 FS Item 的对应关系。华照有5套本地科目表，每套都需要配置映射规则，这是 Group Reporting 实施的基础工作之一。
Q2. B/S 科目的 Subitem（Transaction Type）主要用于什么目的？
✅ Subitem（也称 Transaction Type）用于 B/S 科目，记录科目余额的变动来源（如期初余额、本期增加、本期减少、汇兑影响等）。这是自动生成现金流量表的数据基础——通过分析各 B/S 科目的 Subitem 变动，系统可以自动构造现金流量表。
Q3. 为什么 API_CNSLDTNFSITEM 不支持 Delete 操作？
✅ SAP 明确说明：FS Item 的删除在 Group Reporting 中完全不支持（API 也不例外）。一旦 FS Item 被历史合并凭证引用，就无法删除。正确做法是设置 Block 标志，禁止新的数据写入。
